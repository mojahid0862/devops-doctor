# DevOps Team

This is the canonical coordination workflow for main agents, including direct specialist invocations: assess → map → dispatch → reassess → validate/combine. Read [the shared evidence contract](../devops-doctor/references/evidence-contract.md) once unless already supplied unchanged. Installing this skill adds neither an agent runtime nor permissions. Assigned workers execute their scope; they do not load coordinator skills or repeat team planning unless assigned coordination.

For each fresh substantial task, build one shallow map from current raw evidence: files/diff, jobs, billing/utilization, plan changes, or resources. Identify ready independent questions without relying on old answers. Batch trivial or tightly coupled checks; preserve actual dependencies. A single service may contain useful independent questions. For broad backend health, use [the backend health workflow](references/backend-health.md); dispatch known groups before completing a serial sweep.

## Select a team

1. Use native create/spawn, message, wait and interrupt tools with their current schemas. One main agent may coordinate up to **20 concurrent subagents across all descendants**, excluding the main agent. This is a shared ceiling, not a target or per-worker allowance. Determine free capacity from current host limits and occupied slots, including the main agent if the host does. Neither a configured ceiling nor a previous run's width proves availability. Do not substitute nested Codex processes, agent-creation API calls or user-owned chats. If native delegation is unavailable, disclose it and perform scoped checks sequentially; a requested independent-agent audit remains a capability gap.
2. Initial width = minimum of ready substantial packages, free native worker slots, remaining shared 20-descendant budget, and any explicit task limit. Partition by independently executable module, service/resource, job, region or question. Do not bundle many ready investigations into one or two oversized assignments to reduce agent count. Apply real access, rate or hard-budget constraints; token preferences call for narrow context and reuse, not serialization. Keep small/dependent work direct; invent no work to fill slots.
3. Select only relevant [specialist roles](references/roles.md), repeating roles for distinct scopes as needed. Briefly state initial width and its work/capacity basis; explain actual constraints when substantial work has only one or two ready branches. The coordinator owns sizing, expansion, reuse and reduction without routine approval prompts. Inherit the current model unless user or applicable instructions request otherwise.

For continuations, compare prior canonical coverage with current scope, source revisions and mutable-state freshness. Reuse compatible workers and verified unchanged analysis; refresh changed, uncertain or stale evidence and requested checks. A requested independent audit derives its own conclusions. Label unchanged-source rechecks and compare them separately from fresh investigations in performance reports.

## Delegate with boundaries

- Prefer isolated-context spawn (for example `fork_turns: "none"`) for self-contained work, inheriting the selected model. Supply only task ID/question, exact scope and success condition, essential user/authorization constraints, ownership, relevant specialist, and sanitized evidence pointers. Use broader history only when needed. Do not reload unchanged team/contract instructions already supplied. Workers need their scoped obligations, not another coordinator planning pass.
- Give each remote collection and writable path one owner. Reviewers share immutable local evidence; shared workspaces are not isolated worktrees. Workers default to investigation/review and may perform authorized reversible local edits only in assigned paths. Root retains production mutation, merge/push and external-message execution under existing authorization. Workers may spawn descendants only for coordinator-assigned child tasks within the shared budget. Blocked workers return blockers without changing credentials, broadening scope or indefinite retries.
- Share source/collection/test receipts: identity, revision/blob or resource/window, evidence location, read coverage, observed time and completeness. Apply [reuse and complete-source rules](../devops-doctor/references/investigation-efficiency.md#evidence-reuse-and-bounded-reads); use its [pinned-source reader](../devops-doctor/references/investigation-efficiency.md#pinned-source-reader) for large/batched reads. Verify repository identity and required objects; unknown identity stays provisional/blocked. Refresh affected evidence and mutable state when the claim requires it.
- Give workers the scoped text-relay rule: emit sanitized tool text once with status/coverage metadata separately, avoiding nested JSON encoding of large source/log bodies. Preserve all errors, stderr and truncation markers; this changes representation, not evidence.
- Run independent investigators together. Tests and independent review may overlap on a frozen patch with separate temporary outputs; edits invalidate affected results. A reviewer may reject unsupported partial evidence, but blocked required tasks prevent a complete aggregate.
- Choose one canonical worker result: compact message/table or required report, with findings, relevant negative findings/controls, source pointers, revision/observed time, confidence, gaps/blockers, changed paths and tests actually run. Keep necessary bulk evidence separate. Follow-ups contain only changed/new facts and pointers. Use [handoffs](references/handoffs.md) and `agent_handoff.py` only when a durable/resumable handoff helps; team size does not require JSON artifacts.

## Reassess team size during the task

- Track ready/running/blocked/completed scopes, dependencies and worker count. Reassess after a result, new scope, blocker or material delay; do not wait for all workers. Fill free capacity using the sizing rule and revisit oversized assignments/stragglers for independent parts. A pending job, missing credential, rate limit or unresolved prerequisite needs resolution, not duplicate workers.
- Reuse compatible idle workers when their context helps; otherwise provide a concise fresh handoff. Before splitting active work, agree retained/delegated scopes with its owner and stop or obtain acknowledgment of relinquished ownership. Preserve completed evidence and invalidate only affected conclusions.
- Reduce/release idle workers as ready work decreases. Idle/interrupted workers may still occupy host slots; verify availability before replacements. Stop obsolete/duplicate work and briefly explain meaningful team changes. More workers require useful parallel work, not elapsed time alone.

## Coordinate and finish

1. **Before deep main-agent investigation or any wait, dispatch ready useful branches within capacity.** Require only each branch's own inputs, prioritize downstream unblockers, and work on a distinct scope while workers run. Dispatch newly ready work without waiting for unrelated slow branches or a planning batch; share critical discoveries promptly.
2. Use bounded waits and meaningful updates. Silence/time is not completion. On cancellation, scope change, duplicate work or exhausted user budget, interrupt affected workers and collect partial findings. For performance claims, verify execution overlap from native start/end receipts and measure coordinator-plus-worker usage when available; dispatch counts alone do not prove parallelism.
3. Reconcile contradictions against source/time/scope, not majority vote; request narrow verification or retain the unresolved disagreement. Assign independent review when security/production risk, complexity or uncertainty warrants it, rather than file count. Give raw evidence/immutable patch without prior conclusions as an answer key. Reuse compatible safe test harnesses and source receipts; independent analysis does not require duplicated collection or recreated tests.
4. Inspect decisive evidence, integrate permitted changes and run the smallest relevant final checks. Reference or merge canonical findings into one answer without rewriting every result into extra schemas, indexes, checklists or reports. Extra formats require a consumer or distinct verification need. Preserve required coverage, negative controls, uncertainty and partial evidence; proposed checks are not completed checks. Consensus or a handoff validator exit code cannot establish deployment, merge or remediation success.

Keep a minimal participation roster from native receipts, execution status and returned work. Check known IDs/current-task prefix with metadata-only status where supported; request global capacity metadata only when needed. Do not read unrelated historical findings to count workers. Record actual identity, assignment and outcome, including descendants. Count each confirmed executing worker once, even when reused; exclude unrelated history, planned roles, failed spawns, unstarted dispatches and simulations. State uncertainty if execution cannot be verified.

Conclude with result, decisive evidence, gaps and `Changed | Validate | Next`, including `Agents used: 1 main + N subagents = T total` (N distinct confirmed participants, T = N + 1; zero when alone). Disclose failed/cancelled/partial outcomes. Total participation does not imply simultaneous execution; report verified peak concurrency separately if useful. Avoid worker-ID/transcript dumps or claims of continued monitoring.
